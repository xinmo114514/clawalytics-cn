# Clawalytics 项目优化计划

## 项目概述
Clawalytics 是一个面向 Claude Code 与 OpenClaw 的 AI 成本分析仪表盘，使用 Electron + React + Express + SQLite 技术栈。

---

## 一、性能优化

### 1.1 AnalyticsService 查询优化 (高优先级)
**问题**: `getTodayCost`、`getWeekCost`、`getMonthCost` 等方法每次都遍历所有 sessions 数据，重复计算。

**优化方案**:
- 在内存中维护预计算的聚合数据（today/week/month costs）
- 当 session 数据变化时，增量更新这些聚合值，而不是每次查询时重新计算
- 利用 `_dailyCosts` 缓存（已有），但未充分利用

**文件**: `src/server/services/analytics-service.ts`

### 1.2 WebSocket 广播优化 (中优先级)
**问题**: `broadcast` 函数对每个客户端都执行 `JSON.stringify(event)`

**优化方案**:
- 将消息序列化一次，然后对所有客户端复用
- 考虑添加心跳机制和连接状态管理

**文件**: `src/server/ws/index.ts`

### 1.3 React Query 请求去重 (中优先级)
**问题**: Dashboard 页面有 4-5 个查询使用相同的 `refetchInterval: 10000`，可能导致同时发起多个请求。

**优化方案**:
- 使用 `queryClient:fetchInfiniteQuery` 的 `staleTime` 策略错开刷新时间
- 或者在服务端实现批量 API，将相关数据一次返回

**文件**: `src/client/features/dashboard/index.tsx`, `src/client/main.tsx`

### 1.4 React 组件优化 (低优先级)
**问题**: 多个组件在父组件重新渲染时会不必要地重新渲染。

**优化方案**:
- 对纯展示组件添加 `React.memo`
- 使用 `useMemo` 和 `useCallback` 优化计算密集型组件

## 二、安全优化

### 2.1 CORS 配置 (高优先级)
**问题**: 当前 CORS 配置过于宽松 `app.use(cors())`

**优化方案**:
```typescript
app.use(cors({
  origin: process.env.NODE_ENV === 'production'
    ? ['http://localhost:9174', 'your-production-domain']
    : true,
  credentials: true,
}));
```

**文件**: `src/server/index.ts`

### 2.2 敏感信息泄露 (中优先级)
**问题**: WebSocket 错误处理和解析错误可能泄露敏感信息到控制台/日志

**优化方案**:
- 错误消息脱敏处理
- 生产环境不输出详细堆栈

**文件**: `src/server/ws/index.ts`, `src/server/services/analytics-service.ts`

### 2.3 API 限流 (中优先级)
**问题**: 没有 API 限流机制

**优化方案**:
- 添加 `express-rate-limit` 中间件
- 对高频端点（如 stats）实施更严格的限流

**文件**: `src/server/index.ts`

### 2.4 移除 console.error 生产输出 (低优先级)
**问题**: `console.error` 在 WebSocket 错误处理中被使用

**优化方案**:
- 替换为结构化日志库（如 `pino`）
- 统一日志级别控制

## 三、代码质量

### 3.1 类型定义重复 (中优先级)
**问题**: `Stats`, `EnhancedStats`, `TokenBreakdown` 等接口在 `src/client/lib/api.ts` 和 `src/server/db/queries.ts` 中重复定义。

**优化方案**:
- 创建共享的类型定义包 `@clawalytics/types`
- 或在 monorepo 中使用 workspace packages

**文件**: `src/client/lib/api.ts`, `src/server/db/queries.ts`

### 3.2 ESLint 规则增强 (低优先级)
**当前规则**: `no-console: error` 但项目中仍有 `// eslint-disable-next-line no-console` 注释

**优化方案**:
- 审查并移除不必要的 console 语句
- 对于需要保留的调试代码，考虑使用 debug 模块或条件编译

**文件**: `eslint.config.js`, 各组件文件

### 3.3 Error Boundaries 增强 (低优先级)
**问题**: React 应用缺少细粒度的 Error Boundaries

**优化方案**:
- 为各功能模块添加独立的 Error Boundaries
- 提供更有意义的降级 UI

**文件**: `src/client/routes/__root.tsx`

## 四、打包与构建优化

### 4.1 Electron 构建优化 (高优先级)
**问题**: `better-sqlite3` 需要原生编译，每次构建都需要重新编译

**优化方案**:
- 在 `postinstall` 中添加更好的缓存策略
- 使用 `electron-rebuild` 确保兼容性

**文件**: `package.json`, `scripts/postinstall.js`

### 4.2 依赖大小优化 (中优先级)
**问题**: 部分依赖可能较重

**考虑方案**:
- `recharts`: 考虑替换为更轻量的 `lightweight-charts` 或原生 SVG
- `framer-motion`: 评估使用场景，考虑用 CSS 动画替代部分场景
- 使用 `pnpm dedupe` 减少依赖重复

**文件**: `package.json`

### 4.3 Tree Shaking 增强 (低优先级)
**当前配置**: 基本的 alias 配置

**优化方案**:
- 确保所有 UI 组件都是 ESM 格式
- 配置 Vite 的 rollup 选项以更好地 tree shake

**文件**: `vite.config.ts`

## 五、开发体验 (DX)

### 5.1 Electron 热更新 (中优先级)
**问题**: 当前 dev:desktop 每次代码变更都需要完全重启 Electron

**优化方案**:
- 配置 `electron-reload` 或 `electron-vite` 实现 HMR
- 使用 `vite-plugin-electron` 整合

**文件**: `vite.config.ts`, `scripts/run-electron-builder.mjs`

### 5.2 TypeScript 配置增强 (低优先级)
**当前配置**: 基本 TypeScript 配置

**优化方案**:
- 启用 `strictNullChecks`
- 启用 `noUncheckedIndexedAccess`
- 添加 `tsconfig.server.json` 特定规则

**文件**: `tsconfig.json`, `tsconfig.server.json`, `tsconfig.app.json`

### 5.3 测试覆盖 (低优先级)
**当前状态**: 没有测试配置

**建议**:
- 添加 Vitest 作为单元测试框架
- 添加 Playwright 作为 E2E 测试框架
- 为核心服务编写集成测试

## 六、数据库优化

### 6.1 查询性能 (中优先级)
**问题**: 部分复杂聚合查询在内存中进行

**优化方案**:
- 将 `daily_costs` 和 `model_usage` 表的预聚合逻辑下沉到 SQLite
- 使用触发器或事务自动维护聚合数据
- 考虑添加物化视图（SQLite 4.3+ 支持）

**文件**: `src/server/db/schema.ts`

### 6.2 数据库连接管理 (低优先级)
**当前配置**: 使用单例模式的 better-sqlite3

**优化方案**:
- 对于并发读取场景，考虑 WAL 模式的优化
- 添加连接池监控

**文件**: `src/server/db/schema.ts`
