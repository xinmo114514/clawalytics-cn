## 根因修复方案：避免首次扫描半成品数据显示为“错误数据”

用户已确认：版本更新后缓存失效，AnalyticsService 需要重新扫描 OpenClaw 数据；扫描期间 `/stats/enhanced` 仍返回 200，前端只看 React Query 的 `isLoading`，于是把当时的 0/部分 sessions 当成最终数据展示。

本次不再修改统计口径，先恢复上一轮误改，再增加扫描就绪状态。

### 1. 恢复上一轮不相关的统计改动
文件：`src/server/services/analytics-service.ts`

- 恢复 `computeAggregatedStats()` 的 `monthCutoff = this.daysAgo(30)`，保持现有 rolling 30-day 语义。
- 恢复 `getEnhancedStats()` 的原有 `monthCost` 计算逻辑，避免把本次“扫描未完成”问题和月份口径问题混在一起。
- 恢复 `SESSION_CACHE_FILE` 为现有文件名 `analytics-session-cache-v1.json`；`SESSION_CACHE_VERSION = 2` 本身已负责缓存格式失效，文件名改动不是本次根因。

文件：`src/server/parser/costs.ts`

- 恢复原有 `cacheCreation + cacheRead` 的 `cacheSavings` 计算公式。本次问题不是缓存节省算法，先不改变用户现有统计结果。

### 2. 在 AnalyticsService 增加明确的扫描状态
文件：`src/server/services/analytics-service.ts`

增加有限状态：

- `scanning`：首次扫描或后台刷新尚未完成（包括 2 秒 debounce 等待期）
- `ready`：一次扫描完整结束，即使没有任何 session 也算 ready
- `unavailable`：OpenClaw 路径不存在
- `error`：扫描失败

增加只读状态信息：

- `status`
- `hasData`（当前内存是否有可用 session 数据）
- `lastScanStartedAt`
- `lastScanCompletedAt`
- `lastScanError` 只返回安全错误码/固定文案，不暴露路径、堆栈或原始异常

状态时序：

- `initialize()` 在存在数据源时，在调度首次刷新前置为 `scanning`；路径不存在时置为 `unavailable`。
- `scheduleBackgroundSessionRefresh()` 在 watcher 触发刷新时也置为 `scanning`，覆盖 debounce 阶段。
- `refreshSessionFilesInBackground()` 正常完成后置为 `ready`，即使扫描结果为空。
- 顶层刷新异常时置为 `error`，并保留已有内存数据；首次扫描失败时 `hasData=false`。
- `shutdown()` 清理为 `unavailable`/无数据状态，避免残留上一次 ready 状态。
- 增加 `getStatus()` getter，供 route 使用。

不改变现有 `/stats/enhanced` 响应结构，避免破坏已有客户端和其他页面。

### 3. 增加独立状态 API
文件：`src/server/routes/stats.ts`

新增：

- `GET /api/stats/status`
- 返回 `AnalyticsStatusResponse`
- 使用 HTTP 200 + `status: unavailable/error` 表示数据源不可用或扫描失败，保持现有 API 兼容性

文件：`src/client/lib/api.ts`

- 增加 `AnalyticsStatus` 类型和 `getAnalyticsStatus()` API 函数。

### 4. Dashboard 等待 ready 后再拉取/展示
文件：`src/client/features/dashboard/index.tsx`

- 增加 `analyticsStatus` query，短间隔轮询（约 1 秒，遵循 `pollWhenVisible`，后台不轮询）。
- 将统计、每日成本、模型、Token、预算等 dashboard queries 的 `enabled` 绑定到 `status === 'ready'`，避免首次扫描时继续读取半成品。
- 所有 KPI 卡片和下方图表在 status 不是 `ready` 时继续显示 Skeleton，不再用 `?? 0` 把未就绪数据伪装成真实 0。
- 顶部现有“实时同步”位置改为可访问的状态提示：
  - 扫描中：`正在扫描 OpenClaw 数据…`
  - 已就绪：`分析数据已就绪`
  - 不可用/失败：显示安全的对应提示
  - 使用 `role='status'` 和 `aria-live='polite'`
- 扫描完成后 status query 变为 ready，依赖 query 自动启用并拉取完整数据；现有 `costs:updated` 继续负责数据变化后的失效刷新。
- 如果状态 ready 但某个 query 本身失败，不再把 `undefined` 渲染成 0，保留 skeleton/错误态，避免再次产生“0 是真实值”的错觉。

本次不新增 WebSocket 事件；状态 API 轮询能覆盖“无数据但扫描完成”的场景，改动小且不改变现有 WS 协议。
